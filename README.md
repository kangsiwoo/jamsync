# 합주싱크 (JamSync)

합주할 때 각자 폰과 이어폰으로 같은 곡을 **같은 타이밍에** 듣게 해 주는 웹앱입니다.
안드로이드와 아이폰 모두 브라우저(Chrome, Safari)로 링크만 열면 됩니다. 앱을 설치할 필요는 없고, 홈 화면에 추가할 수도 있습니다.

## 쓰는 법

1. 한 명(방장)이 **방 만들기**를 누르고 **파일 선택**으로 곡을 고릅니다. 곡 파일은 방장 폰에서 멤버들 폰으로 직접(P2P) 전송됩니다.
2. 나머지는 **초대** 링크·QR을 열거나 방 코드 6자리를 입력해 들어옵니다.
3. 멤버 목록에 모두 `곡 ✓`가 뜨면 아무나 ▶를 누릅니다. 1.5초 뒤 모두 동시에 재생됩니다.
4. 일시정지, ±5초 이동, 탐색 바는 누구나 조작할 수 있고, 모두에게 똑같이 적용됩니다.
5. 늦게 들어온 사람은 곡을 받는 즉시 지금 재생 중인 위치에 맞춰 들어갑니다.

### 이어폰 지연 보정

폰 자체의 출력 지연은 앱이 자동으로 보정합니다. 하지만 블루투스 이어폰은 기기에 따라 0.1~0.3초가 더 늦는데, 이건 앱이 알 수 없어서 따로 맞춰야 합니다.

1. **탭으로 자동 측정:** 이어폰을 끼고 딸깍 소리 20번에 맞춰 큰 버튼을 탭하면, 탭이 소리보다 얼마나 늦었는지로 지연을 추정해 줍니다(앞 4번은 연습으로 버림). 리듬게임의 오디오 싱크 설정과 같은 방식입니다.
2. **클릭 테스트로 다듬기:** 클릭 테스트를 켜면 모든 폰이 방장 시계에 맞춰 같은 박자로 딸깍거립니다. 다른 폰과 소리가 하나로 겹칠 때까지 ±5ms로 조절하세요.
3. 보정값은 그 폰에 저장되고, 파일 모드와 유튜브 모드 모두에 적용됩니다. 유선 이어폰이면 0 근처면 됩니다.

탭 측정에는 사람이 박자를 살짝 앞질러 누르는 버릇과 화면 터치 지연이 섞여 있습니다. 그래서 대략값으로 보고 클릭 테스트로 마무리하는 게 좋습니다.

### 유튜브 모드

방장이 **유튜브** 버튼을 눌러 링크를 붙여 넣으면, 모든 폰에서 같은 영상이 방장 시계에 맞춰 재생됩니다.

- **정확도:** 수십 ms 수준입니다(파일 모드는 1ms 안팎). 유튜브 플레이어는 재생 시작 시점과 현재 위치 보고가 거칠고, 재생 속도도 0.25 단위로만 바꿀 수 있습니다. 그래서 위치를 계속 재고, 어긋나면 짧게 1.25배/0.75배로 감아서 맞춥니다.
- **처음에 한 번 탭:** 휴대폰은 영상 안의 ▶를 사용자가 한 번 눌러야 이후 원격 재생이 허용됩니다. 누르면 바로 멈추고 방 상태를 따릅니다.
- **광고:** 광고가 끼면 그 폰만 어긋날 수 있습니다. 광고가 끝나면 자동으로 다시 맞춥니다.
- **재생 제한:** 올린 사람이 다른 사이트 재생을 막아 둔 영상은 쓸 수 없습니다(뮤직비디오 일부).

## 동작 원리

- **시계 맞추기:** 멤버는 방장에게 1초마다 ping을 보내 방장 폰 시계와의 차이를 잽니다(NTP 방식). 왕복이 가장 빨랐던 샘플들만 골라 쓰기 때문에, 셀룰러처럼 지연이 들쭉날쭉해도 몇 ms 이내로 맞춰집니다.
- **예약 재생:** 재생 명령은 "방장 시각 T에 곡의 X초 지점이 귀에 들리게 하라"는 형태로 전달됩니다. 각 폰은 이를 자기 오디오 하드웨어 시각으로 바꾸고, 출력 지연(`getOutputTimestamp`)과 사용자 지연 보정까지 반영해서 Web Audio로 예약합니다.
- **재생 중 보정:** 200ms마다 예상 위치와 실제 위치를 비교합니다. 어긋나면 재생 속도를 ±0.3% 이내(약 5센트, 귀로는 거의 구분되지 않음)로 살짝 바꿔 끊김 없이 따라잡습니다. 35ms 넘게 어긋날 때만 그 자리에서 다시 시작합니다.
- **통신:** WebRTC DataChannel을 씁니다(PeerJS). 처음 서로를 찾을 때만 PeerJS 공개 시그널링 서버를 거치고, 시계 신호와 곡 파일은 폰끼리 직접 오갑니다.

## 셀룰러 환경: TURN 서버 설정 (중요)

- 같은 와이파이, 또는 일반 가정용 공유기끼리는 대부분 그냥 직접 연결됩니다.
- 셀룰러끼리(통신사 CGNAT)나 회사·학교 와이파이에서는 직접 연결이 막히는 경우가 많습니다. 이때는 데이터를 대신 전달해 줄 **TURN 중계 서버**가 필요합니다.
- PeerJS가 예전에 기본으로 주던 무료 TURN 서버는 현재 DNS 자체가 사라져 동작하지 않습니다(2026-11 확인).

[`js/config.js`](js/config.js)에서 둘 중 하나를 채우면 됩니다.

```js
// 1) 자격증명 URL (예: Metered 무료 플랜 — 가입 후 대시보드에서 API 키 발급)
turnCredentialsUrl: 'https://<앱이름>.metered.live/api/v1/turn/credentials?apiKey=<API키>',

// 2) 고정 TURN 서버 (coturn 직접 운영, Cloudflare TURN 등)
turnServers: [{ urls: ['turn:host:3478', 'turns:host:443?transport=tcp'], username: '...', credential: '...' }],
```

TURN을 거쳐도 동기화 정확도는 거의 같습니다. 왕복 시간이 늘어날 뿐이고, 시계 추정이 그 지연을 보정하기 때문입니다.

## 배포

빌드 과정이 없는 정적 파일입니다. **HTTPS가 필요합니다**(화면 꺼짐 방지, 클립보드, 일부 iOS 기능 때문).
아래 중 아무 곳에나 폴더째 올리면 됩니다.

- GitHub Pages: 저장소에 push한 뒤 Settings → Pages
- Cloudflare Pages / Netlify: 폴더를 드래그 앤 드롭하거나 `npx wrangler pages deploy .`

로컬 테스트는 이렇게 합니다.

```bash
python3 -m http.server 8765
```

폰에서 바로 열어 보려면 HTTPS 터널이 필요합니다. 예: `cloudflared tunnel --url http://localhost:8765`

## 아이폰 주의사항

- 처음 방에 들어갈 때 버튼을 누르는 순간 오디오가 켜집니다. 앱을 다시 열었는데 소리가 안 나면 **탭해서 소리 켜기**를 누르세요.
- iOS 17 이상은 무음 스위치가 켜져 있어도 재생되도록 설정해 두었습니다. 그보다 낮은 버전이면 무음 모드를 해제하세요.
- 화면이 꺼지면 Safari가 페이지를 멈춥니다. 앱이 화면 꺼짐 방지(Wake Lock)를 요청하지만, 합주 중에는 앱을 화면에 띄워 두세요.

## 테스트

```bash
node --test test/
```

`test/clock.test.mjs`는 와이파이 수준과 셀룰러+TURN 수준의 지연·지터를 흉내 내서 시계 추정 정확도를 확인합니다.
`test/tap.test.mjs`는 탭 측정 추정과 유튜브 링크 파싱을 확인합니다.
방장 화면의 **테스트** 버튼을 누르면 120BPM 클릭 트랙(90초)을 만들어 실제 동기화를 귀로 확인할 수 있습니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `js/clock.js` | 방장 시계와의 차이 추정 (NTP 방식, 최소 RTT 필터) |
| `js/player.js` | 예약 재생, 출력 지연 보정, 재생 속도 미세 조정, 클릭 테스트, 탭 지연 측정, 테스트 음원 생성 |
| `js/ytplayer.js` | 유튜브 모드 (IFrame API, 위치 측정 후 빨리/느리게 감기로 맞춤) |
| `js/net.js` | PeerJS 방(방장/멤버), 파일 분할 전송, 재연결 |
| `js/config.js` | STUN/TURN 설정 |
| `js/app.js` | 화면과 상태 연결 |
